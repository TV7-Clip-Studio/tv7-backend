# Forgotten App → Shorts Factory

## System Purpose
The FastAPI service turns long-form YouTube videos into ready-to-publish vertical shorts. An operator pastes a YouTube link, the system handles ingestion, AI highlight detection, automated clipping with stylized subtitles, and exposes the resulting assets for review, approval, and (stubbed) publishing. Everything lives inside this single application: API, background pipeline, storage metadata, and an internal admin dashboard.

## Core Domain Model
- **Video**
  - `id`: primary key.
  - `source_url`: original YouTube link.
  - `local_path`: filesystem or object-storage location of the downloaded full-length video.
  - `transcript_text`: full combined transcript/closed captions.
  - `status`: lifecycle state (`ingested`, `processing`, `ready`, `error`).
  - `created_at` / `updated_at`: timestamps.
- **Clip**
  - `id`: primary key.
  - `video_id`: foreign key to `Video`.
  - `start_sec` / `end_sec`: clip boundaries in seconds.
  - `local_path`: rendered 9:16 mp4 with subtitles burned in.
  - `caption_text`: hook/CTA text generated by the LLM.
  - `status`: lifecycle (`rendering`, `ready`, `published_partial`, `published_all`, `error`).
  - `created_at` / `updated_at`: timestamps.
- **PublishJob**
  - `id`: primary key.
  - `clip_id`: foreign key to `Clip`.
  - `platform`: target platform identifier (`youtube_shorts`, `tiktok`, `instagram`, etc.).
  - `status`: job state (`pending`, `success`, `error`).
  - `response_data`: JSON/text payload from the platform or stub.
  - `created_at`: timestamp.

These tables represent the single source of truth for processing state. Background workers should transition statuses atomically and leave audit trails when failures occur.

## Processing Pipeline
1. **Ingestion**
   - Endpoint `/videos/ingest` accepts `{ "youtube_url": "..." }`.
   - Creates a `Video` row (`status=ingested`) and enqueues the full pipeline.
   - `services/youtube_downloader.py` downloads the best-available video stream plus captions/transcripts, returning local file paths and transcript text.
   - Persist `local_path` and `transcript_text` on the `Video`.
2. **Highlight Detection**
   - `services/highlight_detector.py` sends the transcript to the LLM.
   - Response yields 3–5 segments with `{start_sec, end_sec, hook}`.
   - Creates `Clip` rows for each segment with `status=rendering` and stores the hook text in `caption_text`.
3. **Clip Rendering & Subtitle Styling**
   - `services/clipper.py` uses ffmpeg to cut each segment, reframe to 9:16, and export lossless mezzanine files.
   - `services/subtitle_styler.py` overlays high-contrast subtitles sliced from the transcript segment.
   - Final assets saved to storage; update each `Clip` (`local_path`, `status=ready`).
4. **Video Completion**
   - When all clips reach `ready`, update the parent `Video.status="ready"`.
5. **Publishing (Stubbed)**
   - Endpoint `POST /clips/{clip_id}/publish` accepts `{ "platforms": [...] }`.
   - Creates `PublishJob` rows and (for now) marks them `success` immediately with a fake `posted_at`.
   - Update `Clip.status` (`published_partial` or `published_all` depending on coverage).

The pipeline must execute outside the request/response loop (Celery/RQ/Dramatiq/background tasks). Failures should set the relevant status to `error` and surface diagnostic information for operators.

## API Surface
- `POST /videos/ingest` — queue processing for a YouTube URL. Returns `{ "video_id": ..., "status": "queued" }`.
- `GET /status/{video_id}` — poll overall video status plus per-clip progress snapshots.
- `GET /videos/{video_id}/clips` — list generated clips with timing, caption text, preview URLs/paths, and status.
- `POST /clips/{clip_id}/publish` — create `PublishJob` records and trigger (stubbed) publishing automation.
- `GET /admin/videos` — HTML dashboard of videos, statuses, and navigation to detail view.
- `GET /admin/videos/{video_id}` — HTML per-video view showing clip previews, metadata, and publish buttons hooked to the publish endpoint.
- All admin-prefixed routes require HTTP Basic auth; credentials are supplied via `ADMIN_USERNAME`/`ADMIN_PASSWORD` environment variables.

All endpoints remain within the FastAPI application. Swagger `/docs` should describe request/response contracts for the JSON APIs; admin routes can remain simple HTML templates for internal use.

## Operational Notes
- **Storage:** Local disk works for development; abstract via settings so object storage (S3, GCS) can be introduced later.
- **Background Execution:** Use a task queue (e.g., Dramatiq, RQ, Celery) or FastAPI `BackgroundTasks` wrapper that delegates to worker processes. Never block the ingest request on downloading or rendering.
- **Observability:** Record timestamps and durations per pipeline stage; expose them via logs and metrics to surface bottlenecks (download time, LLM latency, ffmpeg performance).
- **Admin credentials:** Rotate the HTTP Basic credentials via `make admin-credentials` (writes to `.env`, syncs Fly secrets, and prints the values) before deploying.
- **Extensibility:** Additional services (thumbnail generation, branded overlays, true publisher integrations) should build atop these core models without splitting the codebase.
